Why this is a decision

A3 chose one palette that routes to whatever surface fits, and Lorenzo's amendment pulled one thing back out of it: the shortcut vocabulary has to work the same way on macOS, Windows and Linux. A3's own keyboard table is written entirely in Mac notation, ⌘K for the palette, ⌘⇧A for Ask, and it already reserves bare letters, A/R for accept/reject, J/K for move, for C6's queue, without saying whether "bare" survives the amendment at all. That page now says so directly: the actions are settled, the exact keys are not, and points here. Everything below has to answer three things at once: which modifier a given action gets on which platform, whether any key stays bare, and what already belongs to the browser, the screen reader, or a keyboard layout that is not the one this was tested on.

Guardrail 1 propose, never apply, no accept-all, ever. A3 already reserves A/R for the item in focus, never a range, never "all". Whatever the cross-platform map below turns out to be, no single chord may read as "accept everything," and none may land on CtrlA, which the browser already spends on "select everything" and a GM's hand is one habit away from confusing with the other.

Options

A

Everything modifier-based, Cmd maps to Ctrl

One rule for every binding this decision introduces: always a modifier, ⌘ on macOS reduces to Ctrl on Windows and Linux for the identical combination. C6's existing bare keys are left as a grandfathered exception, not reopened.

Buys

  • One predictable rule for every shortcut invented from here forward: see a modifier, know it maps.
  • Nothing already shipped in C6 has to be relearned or retested.
  • Chorded bindings are the ones a screen reader's own single-letter navigation never intercepts, unlike a bare key.

Costs

  • Next/previous on [/] needs AltGr on an Italian or German layout to type at all, the identical problem B2's [[ mention trigger already has.
  • Leaves an unprincipled seam: C6 is bare because it shipped first, not because bare belongs there, and nothing here says which is true for the next surface.
  • ⌘Z/CtrlZ is already the OS and browser's own text-field undo; binding it again for "undo my last review action" risks undoing the wrong thing the instant a GM is also mid-sentence somewhere else on the page.
B

Bare keys inside a review surface, modifiers everywhere else

The split is explicit policy, not an accident of shipping order. j k a r u stay bare inside a focused review surface, C6 and D4's own queue; everything reachable from anywhere else in the app, the palette, Ask, save, keeps a modifier.

Buys

  • Bare letters need no cross-platform map at all: a is a on every OS, which is most of the actual amendment solved for free.
  • Matches what C6 and D4 already ship and were already reasoned about; nothing built gets thrown away.
  • u for undo never collides with the OS or browser's own CtrlZ, because it only fires while the queue itself has focus.

Costs

  • The boundary, what counts as "a review surface with real focus", has to be spelled out precisely: does D4's chip-filtered list count, does a palette search result list count.
  • Two vocabularies is one more thing to teach than a single rule, even if each half is individually simpler.
  • A GM who lands on the queue by a direct link, never having opened the palette, has no prior exposure to "letters work here" and needs an on-screen hint the first time.
C

Modifiers only, no bare keys anywhere

The maximal version of A: no exception, no grandfathering. C6's own j k a r u get rebound to chords too, so the product has exactly one kind of shortcut, everywhere, always.

Buys

  • The simplest possible mental model to state: a shortcut always needs a modifier, no exceptions, no "except inside this one screen."
  • Removes any risk of a bare letter firing while a screen reader's own quick-navigation is active, since a modifier changes the key event a browse-mode reader would otherwise intercept.
  • Every shortcut is legible from the palette's own reference list using one notation, nothing to footnote as "letters only, and only here."

Costs

  • Rebuilds and re-tests C6, already shipped, already praised on its own page for being "the vocabulary a GM who has reviewed a pull request already has," for a purity rule with no concrete benefit to that specific screen.
  • Slower under a real ten-entry review: a chord takes measurably longer to execute than a bare key for the single most repeated action in the product, which is the entire reason C6 chose bare keys in the first place.
  • Buries the actual guardrail 1 protection, per-item only, never a range, under the same chord shape as everything else, so nothing about the keys themselves reminds anyone of the constraint the way a lone unmodified letter does.

The vocabulary, real keys, three platforms

Built under option B, since bare keys need no per-platform row of their own. Local overrides inside a genuine text field still win, browser undo included, everywhere else these are reserved.

Rejected outright

Reopen A3's global accept-all shortcut under a new, "safer" chord

The amendment makes it tempting to revisit every A3 shortcut decision at once, and a single chord for "clear the visible queue" resurfaces easily under the cover of "modernising for three platforms." It is the same failure A3 already rejected, now with a cross-platform coat of paint. Guardrail 1 forbids an accept-all default in any form, on any platform, under any modifier. Whatever this page settles for the six "everywhere" actions and the five bare ones, none of them may resolve to more than one proposal at a time.

What I would take

B, bare keys inside a review surface, modifiers everywhere else

Take B. It is the only option that treats the amendment as what it actually is, a mapping problem for the six actions that live "everywhere" in the app, not a reason to reopen C6's already-shipped, already-argued-for bare keys. A modifier genuinely needs a cross-platform table, because ⌘ and Ctrl are different keys in different places on different keyboards. A bare letter does not: it is the same physical gesture everywhere, which is most of the actual cross-platform problem solved by not having one. C pays real speed and real rework to remove that advantage for a consistency argument that has no user standing behind it; A leaves the inconsistency between "some things are chorded, some are not" unexplained instead of naming it as policy the way B does.

How a shortcut gets discovered: the palette is the front door for all of it, so it is also the reference. A bare ?, outside any text field, the same rule that keeps a/r safe, opens a full list; typing "shortcuts" into the palette itself routes to the same list, since C's whole premise is that the palette routes to whatever surface fits; and every result row in the palette already shows its own bound key as a trailing hint, so opening the palette at all is a small, constant advertisement for the vocabulary, not just a search box.

Cheapest way to find out this is wrong: ship the ? reference first, it is one static list, and watch whether GMs on Windows and Linux ever find j/k/a/r/u without opening it. If nobody finds the bare keys unaided, "no modifier needed" solved the smaller problem, the map, at the cost of the bigger one, discovery, and the queue needs a permanent on-screen hint rather than relying on being memorable.

What this locks in

  • #104 the shell renders the palette's trigger, and the ? reference it opens, identically on every screen, on every platform; whichever shape A2's shell takes, this is one component it hosts, not one it reinvents per surface.
  • #75 the palette's entity search still has to hit the instant lane, <100ms, on every platform's keyboard event path; a heavier cross-platform modifier-detection layer in front of it must not be where that budget gets spent.
  • #51 the accept/reject surface, C4's in-place diff and C6's queue together, ships with bare keys that are OS- and layout-proof by construction, unshifted ASCII needs no per-platform code path at all, only the "everywhere" entry points around it do.
  • Hard to undo: once a GM's hand has learned a/r for a review surface, moving that vocabulary onto a modifier later breaks a trained reflex, not a config file.
  • Deferred on purpose: G4's slash-menu trigger inherits the same non-US-layout problem [[ already has, since / also is not where a US layout puts it on every keyboard; that collision is G4's to resolve, not re-decided here.
