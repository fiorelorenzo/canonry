Why this is a decision

The spec fixes the stack (Tailwind 4, shadcn-svelte) and nothing about the language: no type scale, no density, no default theme. That is fine until the first component lands, because shadcn ships a neutral default that quietly becomes the product's face by inertia. The awkward part is that Canonry has two rooms with opposite requirements. Prep is an hour at a desk reading and writing prose, which wants a comfortable measure and calm contrast. Table mode is ten seconds in a dim room with dice in one hand, which wants large targets and contrast that survives a glance. One skin has to serve both, or the switch between them has to be a deliberate part of the language rather than an afterthought.

There is also a colour constraint that is not aesthetic. AI text must be visually distinct (decision C1 works out how), so one hue is spent on "proposed, not yours". If the brand accent is that same hue, the marking stops reading as a warning and starts reading as decoration.

Guardrail 4 with the AI switched off, what is left must still be a good wiki. A skin that only looks intentional when it is full of violet AI chrome fails that test, so each option below is worth checking twice: once as drawn, once with the copilot column gone.

Decided

B, the reading room, taken on 2026-08-13

Decided B rather than the A recommended below, so the reading room is now the product's palette and not a candidate: warm paper, serif for canon prose and entry titles, burnt umber accent, violet still spent only on the copilot. The shared stylesheet has been cascaded to match, which is why every mock in this set, on every page, is already wearing it.

B was the option that shipped the least, and that is the part worth being explicit about rather than quietly assuming: it came with no dark theme and with a density tuned for reading prose, while the copilot's surfaces are all lists, diffs and queues. Both halves became their own decisions instead of being settled inside the first component that trips over them, which is exactly the failure this whole set exists to prevent: G1 decided dark as a whole-app preference that table mode inherits rather than forces, and G2 decided serif keeps going all the way down, with no boundary and no exception for a dense surface.

The three options below stay as drawn, with A and C carrying their palettes locally, because a decision keeps its value only while the alternatives it beat are still legible.

Options

A

Quiet tool

Light, sans throughout, dense rows, one accent used sparingly. The register a code editor or a tracker uses: the chrome disappears and the content carries the page.

Body system sans 14/1.6 Title sans 26 semibold Row height 32px Accent deep green, links and primary only Measure 38em

Buys

  • Reads as a tool, which is what a GM comparing against Obsidian expects.
  • Density fits the graph work: relations, proposals and facts all want lists.
  • Nearest to shadcn's defaults, so components arrive already dressed.

Costs

  • Nothing about it says fantasy, and the landing page has to carry all the warmth.
  • 14px sans at 1.6 is a poor place to read six paragraphs of prose.
  • Generic: three tools on this board could wear the same skin.
B

Reading room

Warm paper, serif for entry titles and body, wider leading, softer density. The wiki as a book someone keeps, with the tool parts staying sans.

Body serif 16.5/1.8 Title serif 26 Row height 36px Accent burnt umber Measure 34em

Buys

  • Prose is genuinely pleasant to read and to write, which is most of prep.
  • Has a face. A screenshot is recognisable, which the landing page needs.
  • Warm paper makes the violet AI marking read as intrusion, which is the point of it.

Costs

  • Every dense surface fights the skin: diffs, proposal queues, import tables.
  • Serif plus warm paper is one taste away from twee, and taste is not testable.
  • Worst of the three at a table in a dim room.
C

Dark console, table first

Dark by default everywhere, 15px base, taller rows, high-contrast accent. Optimised for the room the product is used in during play.

Body sans 15/1.6 Title sans 26 Row height 38px Accent mint, high contrast Measure 38em

Buys

  • The only option that is already right for the room where table mode runs.
  • Taller rows are also the phone layout (E4), so one density serves both.
  • Generated images and portraits sit better on dark panels.

Costs

  • Dark by default is a minority preference for long reading and writing.
  • Red and green diffs need reworking on dark, and so does the violet AI tint.
  • Landing page and players wiki almost certainly want light anyway, so a second palette exists regardless.

Rejected outright

A parchment-and-woodcut fantasy skin

Textured backgrounds, drop caps, a display face for headings. It reads well in a screenshot and badly after twenty minutes, it makes a diff nearly unreadable, and it puts the product in the same visual family as the tools this one is trying not to be (02 the competitor is Obsidian, and Obsidian is plain on purpose). The world's flavour belongs in the images the GM generates and in their own prose, not in our chrome.

Violet as the brand accent

It is the current fashion for AI products and it is exactly the hue that has to mean "not yours yet" (C1). Spending it on buttons and links leaves the marking nothing to say, and repainting it later touches every surface at once.

What I would take

A as the base, with B's measure for entry prose and C promoted to a real theme

Take A. It is the only option whose density is right for the surfaces that carry the flagship feature, and those surfaces are lists: plans, diffs, proposals, import tables. Then spend two specific concessions rather than adopting a whole second skin: entry prose gets B's comfortable size and 34em measure, because reading and writing entries is where the hours go; and the dark palette from C ships as a first-class theme, chosen by the system preference, with table mode defaulting to it regardless of the setting.

Concretely: one token file, two palettes, one type scale, sans everywhere with the serif question deferred to B1 where the entry body is actually designed. The accent is the deep green above, and violet stays reserved for the copilot.

Cheapest way to find out this is wrong: build the propagation review screen (C3, C4) first in this skin. If a ten-entry plan and a prose diff look cramped or shouty here, the base density is wrong and it is a token change rather than a redesign. The expensive mistake would be discovering it after fifty components exist.

What this locks in

  • #104 ships the token file and both palettes, not just a shell. A theme retrofitted after the components is how a product ends up with hardcoded greys.
  • C1 inherits violet as the AI hue in both palettes, and has to prove the dark variant is still unmistakable rather than merely pretty.
  • E1, E4 inherit "table mode is dark by default" and taller rows, so the table surfaces are not a separate design system, only a separate density mode.
  • #3 the landing page is light and can be warmer than the app, but it may not show a skin the product does not have.
  • Deferred on purpose: whether entry prose is serif. That belongs to B1, where the body is designed against real content rather than two paragraphs of fixture.
