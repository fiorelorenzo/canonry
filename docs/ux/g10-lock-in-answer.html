Why this is a decision

F4 decided the export itself: a flat zip of markdown files, wikilinks, an images folder, reachable only from Settings → Data, taken against the recommendation of a git-ready folder advertised on the landing page. SPEC 13 ships the export on day one for a specific reason: it costs little and it is the answer to the lock-in objection Realm Works burned into this community's memory. SPEC 15 rejects opaque credits for the identical reason: this product's honesty about the exit is supposed to be a selling point, not a feature nobody hears about until they go looking in Settings. F4's own decision record says this out loud: "an unadvertised feature answers nobody." That is the gap this page has to close, or explicitly choose to leave open.

SPEC 13 "Markdown export ships from day one, because it costs little and it is the answer to the lock-in objection Realm Works burned into this community's memory." SPEC 15 "No opaque credits, and never the word unlimited," the same plain-words standard this page has to meet for a different promise.

Options

Every candidate sentence below is written against the export F4 actually decided: a flat zip, per entry, wikilinks and frontmatter, no typed folders, no README, no git tooling. Any sentence that implies more than that is flagged, not offered as a real candidate.

A

Landing, below the demo, plus a docs page

F6 already spent the fold on the accept-button demo with no copy above it. One line sits in the strip below it; a docs page carries the real detail: what a file looks like, what is not included, how to point Obsidian at the zip.

Buys

  • Reaches every visitor before signup, the exact moment F4's own record says the feature has to reach someone to do its job.
  • A docs page can go into the frontmatter fields and the flat-versus-folder distinction in full, without competing for the landing page's one sentence.
  • Costs one sentence of space on a page that already has a below-the-fold slot to put it in.

Costs

  • F6 chose the demo precisely because it is the strongest thing on the page; a second sentence below it, however short, is still something to weigh against adding nothing at all.
  • A docs page is one more surface that has to be kept in sync with F4's actual zip contents whenever the export changes.
  • A visitor who never scrolls past the demo, and F6's own numbers may show plenty do not, never sees this sentence either.
B

Pricing and data-and-privacy pages only

Nothing changes on the landing page. A line lives in the pricing page's plan comparison and again in the data-and-privacy page, both places a skeptical GM already reads before paying.

Buys

  • Both are pages a skeptical GM already visits when deciding whether to pay, meeting the objection at an actual decision moment without touching F6's careful demo-first landing page.
  • The data-and-privacy page is a natural home: export is fundamentally a data-ownership property, read by exactly the audience worried about lock-in.
  • Nothing about F6's hard-won "no copy above the fold" decision is reopened or renegotiated.

Costs

  • A GM who never gets past the landing page, because the demo alone did not convince them, never sees the objection answered at all.
  • Two lower-traffic pages reach a narrower slice of the same skeptical audience the landing page could reach directly, at the exact moment they are deciding whether to keep reading.
  • Two places to keep in sync with F4's actual export contents instead of one.
C

Keep it silent, as chosen

F4's decision stands exactly as recorded: the export exists, reachable only from Settings → Data. Nothing on the landing page, the pricing page, or anywhere else says so.

Buys

  • Zero marketing surface to write, review or keep current: the export's copy exists in exactly one place, next to the button it describes.
  • Nothing on the landing or pricing page implies "you might want to leave," which some read as a cleaner, less defensive pitch.
  • No public claim about the export's contents to be held to if the format ever changes.

Costs

  • The objection SPEC 13 names goes unanswered exactly where it is raised: before signup, by a GM comparing this product to the last one that trapped their world.
  • F4's own decision record already flags this: "an unadvertised feature answers nobody," written the day the silent option was chosen.
  • SPEC 15's "no opaque credits" standard has a public answer on the pricing page; SPEC 13's lock-in standard, paid for the same reason, has none anywhere a visitor can read before paying.

Rejected outright

"Git-ready markdown export, so your world is never locked in."

This describes the option F4 did not choose. The decided export is a flat zip: no typed folders, no README, no .gitignore, no relative links resolved for a repository layout. Advertising "git-ready" anywhere a GM can read it before downloading the file is a claim about a data property that is not true today, exactly the kind of statement Guardrail 5 requires plain words for. If the git-ready shape ships later, per F4's own deferred note, the sentence can be written truthfully then, not before.

What I would take

A, one sentence below the demo, plus the docs page

Take A. It puts the sentence where a skeptical GM actually reads before signing up, which is the entire premise SPEC 13 pays for and F4's own record already names as the failure mode of staying silent: "an unadvertised feature answers nobody." It does this without touching F6's demo, which is the single most important piece of copy on the page and stays exactly as decided: the sentence goes in the strip already sitting below the fold, not above it. Use the first candidate from the table: "Export your whole world as markdown, any time, from Settings," a docs link, nothing more. It names the real feature, in the real place it lives, without a promise the flat zip cannot keep.

Cheapest way to find out this is wrong: ship the one sentence and the docs page alone, skip B's pricing and privacy lines for now, and watch signup and bounce rate among traffic referred from Obsidian, Kanka and World Anvil communities, the visitors most likely to be carrying the Realm Works memory SPEC 13 names. If that segment's behaviour does not move, the fix is more likely B, meeting them at pricing where money is actually being decided, than a louder version of the same landing sentence.

What this locks in

  • #21 gains a public sentence describing the flat zip exactly as F4 decided it, no folders, no git tooling, so marketing copy has to be re-reviewed the day export's contents change, not after.
  • #3's landing page carries this line in the below-the-fold strip already reserved for other copy, so this sentence and whatever else lands there have to be written to fit together, not added independently in a later pass.
  • #109's data-and-privacy page is not this decision's chosen surface, but the docs page and the privacy page both describe the same export, so their copy has to agree with each other and with Settings, three places, one fact.
  • Hard to undo: once a specific sentence about the export's actual contents ships publicly, it becomes a documented claim about data portability; quietly changing the export format later without updating every place this sentence lives turns true copy into false copy.
  • Deferred: whether the fuller git-ready diagram from F4's own original recommendation ever gets built and promoted is not decided here, it stays gated on real usage, per F4's own recommendation.
