# The review rubric

Every screen in `SURFACES.md` gets checked against these before its issue moves to Done.
They are the guardrails restated as questions somebody can answer while looking at a pull
request. Rescued from `docs/ux/index.html`, deleted 2026-08-23 (readable in git history at
`c84c8f8`), because `AGENTS.md` still points a fresh agent here for the rubric the
guardrails turn into.

## 1. Propose, never apply

Is there any path where model output lands in canon without a human pressing accept on
that specific entry? Is there an accept-all anywhere it is not explicitly permitted?

## 2. AI text is distinct

Can a GM tell proposed text from their own at a glance, in both palettes, without relying
on colour alone? Is accepted AI text still traceable a month later?

## 3. Evidence, never a score

Does every proposal name the entry and the sentence it came from? Is there a percentage
anywhere pretending to be a reason?

## 4. The AI switches off

With the copilot off, is this screen still coherent, or is it a shell with a hole in it?

## 5. Data transparency

At the moment content leaves for a provider, can the GM find out which one and what
happens to it, in a sentence rather than a policy?

## 6. Nothing unreviewed reaches players

Can anything on this screen reach the players wiki without an explicit reveal? Generated
images included.

## 7. Never promise consistency

Does any string here claim the canon is consistent, verified, or coherent? Detection sits
around F1 52%, so the honest verb is "looks".

## The table test

If this screen can appear during play, does anything on it wait on a model? Instant means
under 100 ms from the graph.
