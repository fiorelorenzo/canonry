Why this is a decision

Seven places want to be top-level: entries, works, proposals, table mode, the players' wiki, import and settings, and all of them sit under a universe switcher that is not decoration. A GM with two universes open, one homebrew and one derived from the official Forgotten Realms corpus, needs to always know which layer they are editing, because the user's canon always wins and a specific source page can be superseded and vanish from retrieval (SPEC 4.1). None of that is optional chrome: get it wrong and the Loremaster quotes the published setting back at someone who deliberately diverged from it.

Import complicates the shape further, because it is not one screen visited once. SPEC 6.4 is explicit that a GM imports, works for a month, and re-imports, so import needs an address that survives past day one rather than a wizard that vanishes after first run.

Guardrail 1 whatever holds the nav, it must never let "review your proposals" collapse into a single click that applies all of them. A crowded top level is a reason people reach for shortcuts, and this is the shortcut that is not allowed to exist.

Options

A

Fixed sidebar, universe switcher on top

The shape A1 already drew: a full-height text nav, all seven places listed, the switcher pinned above it. Expanding the switcher shows precedence in place; supersede lives on the entry it protects.

Buys

  • Already drawn: it is exactly A1's sidebar, so #104 ships one interaction pattern, not two.
  • Precedence and supersede are permanently visible, not one tap behind an icon.
  • Recognisable to an Obsidian-native GM on day one; nothing to learn before the import even finishes.

Costs

  • Seven rows plus an expandable switcher is dense before a single Recent entry is added.
  • The aside now competes for the same 268px that Proposals wants on every other page.
  • Does not scale past seven; an eighth place means either scrolling or a fold.
B

Icon rail, contextual second pane

A 56px rail of glyphs, universe swatch on top. Clicking a place that needs more than a destination opens a slim contextual pane next to the rail; the main surface keeps its width.

Buys

  • Widest main column of the three, which matters once C3/C4's plans and diffs live there.
  • One pane pattern serves import status, and later table's context panel, without new chrome.
  • Survives at any window width; nothing to collapse.

Costs

  • Seven two-letter glyphs are a guessing game before muscle memory forms.
  • The universe swatch is one icon among equals, so precedence stops being a glance and becomes a click.
  • Two taps to act on anything: open the rail item, then act inside the pane.
C

Palette-first, thin sidebar

Sidebar carries only the universe name and a couple of pinned shortcuts. Everything else, including Import and Settings, is a result in the command palette.

Buys

  • Nothing competes with the sidebar for pixels, because there barely is one.
  • The same surface that finds an entry also reaches Import and Settings, so an eighth place costs nothing.
  • Reading and writing surfaces get the whole window; table mode inherits it for free.

Costs

  • A GM new to the product, mid Obsidian import, has no visible map of what exists.
  • Universe switching becomes a search query instead of a glance, which weakens exactly the precedence signal SPEC 4.1 asks to be visible.
  • Depends entirely on A3 landing well: if the palette is slow or the wrong result ranks first, this option has no fallback chrome to fall back on.

Rejected outright

A "Sync" button instead of a Proposals row

Once the sidebar is fighting for room, folding the Proposals list into one badge that applies everything on click looks like a clean way to buy back a row. It is exactly the single most hated behaviour the whole product exists to avoid: an agent that edits without asking. Guardrail 1 is not negotiable for the sake of a tidier nav, and there is no git diff to undo it if it ships anyway.

What I would take

A, with a hard cap and an escape valve

Take A. It costs nothing new to build against A1's already-drawn shell, it is the option an Obsidian-native GM recognises without being told anything, and it is the only one of the three that keeps precedence and supersede visible without a click. The density problem is real but bounded: seven places is the whole list forever, SPEC does not describe an eighth, so cap the nav exactly there and put anything that does not fit: the twelfth Recent entry, a search across 214 entries, behind the palette that A3 designs next. The sidebar is the map; the palette is how you actually get anywhere once the map is memorised.

Cheapest way to find out this is wrong: build it against Sword Coast, not Valdoria Reach, because Sword Coast is the only universe where the switcher, the derived badge and a superseded entry are simultaneously true. Put it in front of someone who has never seen the product and time how long it takes them to find the entry that supersedes a Forgotten Realms page on their own. If it is not near-instant, the fixed list is already too dense and the fix is a lighter modifier of B, not a redesign.

What this locks in

  • #104 ships the exact nav item set and universe switcher drawn above, not a placeholder shell that gets restyled later. The switcher's expanded state, with both layers listed, is part of the acceptance criteria.
  • #19 has to make the aside's "superseded, struck through" row real: an entry needs a way to declare it supersedes a source page, and that source page has to actually stop coming back from retrieval, not merely render differently.
  • Import gets a permanent nav address rather than a first-run-only wizard, which is what SPEC 6.4's recurring re-import needs; D1–D7 design what happens once it is opened.
  • Deferred on purpose: the palette's own ranking and result types belong to A3. Table mode's declared-context bar belongs to E1. What Settings actually contains belongs to F2 and F3.
