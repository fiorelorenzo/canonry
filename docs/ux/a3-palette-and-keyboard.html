Why this is a decision

A GM at a desk wants to jump to Aldric Vane without touching the mouse. A GM at the table wants "who is this?" in under a second, inside SPEC 8's fast lane. A GM mid paragraph wants to ask a question without losing the sentence they were writing. All three are keyboard-first moments, and if each invents its own trigger and its own results list, the product has three things to learn instead of one. The spec does not say where Ask lives; it only says Ask exists any time, streams over SSE, and returns sources rather than a bare score. That leaves the palette's scope, and Ask's address, genuinely open.

The other genuinely open question is smaller but sharper: does typing a name and typing a question belong in the same box? A name resolves to one row and a click. A question resolves to a stream, a source list and five detail levels (§5). C8's whole page. Cramming both into one input is not free.

Guardrail 3 every proposal shows its evidence, never a bare confidence score. If Ask's answer lives inside the palette, the palette has to have room for the source list every time, not just when there happens to be space.

Options

A

One box, answers inline

Everything: entities, actions, work nodes, and Ask itself, all resolved and rendered inside the palette overlay. A question streams its answer in the same panel.

Buys

  • One surface to learn, one shortcut, no branching on what you typed.
  • A one-line question gets an answer without ever leaving the flow you were in.
  • Genuinely fast for the common case: "who is Corvin Ashe again?" needs no navigation at all.

Costs

  • Sources, five detail levels and follow-up questions (§5) do not fit an overlay sized for a name.
  • A long answer either truncates the evidence or grows the palette into a second window with extra steps.
  • Duplicates C8 instead of using it: two places now render the same streamed answer.
B

Two surfaces, two shortcuts

The palette finds things and runs actions. Ask is a dedicated surface with its own shortcut; typing a question into the palette does nothing special.

Buys

  • Ask gets the whole surface it actually needs: sources, detail levels, follow-ups, exactly as C8 designs it.
  • The palette stays fast and simple, a pure index over names and actions.
  • No duplicate rendering path for a streamed answer.

Costs

  • A GM who types a question into the wrong box gets a dead end and has to know the second shortcut exists.
  • Two vocabularies for one instinct: "just ask something" now branches on which key you pressed.
  • The failed search is a bad first impression during onboarding, exactly when trust is being built.
C

One box, routes to the surface that fits

Same palette as B for names and actions, but recognising a question is not a failure: it becomes one result that opens Ask in full, not an inline answer.

Buys

  • One instinct, one shortcut: type anything, get somewhere useful, no second key to remember.
  • Ask still gets C8's full surface; the palette is a doorway to it, not a competing renderer.
  • A near-miss on a name and a genuine question can both show up, so a bad guess about intent costs nothing.

Costs

  • Needs a real question classifier, not just "did this match an entity name", which is one more thing to get right.
  • Enter's meaning changes depending on which row is selected, which is one more thing to teach.
  • The routing row has to be visually distinct from a real answer, or people expect the stream to start right there.

Rejected outright

A global "accept all pending" shortcut

Once every action lives behind one keystroke, binding something like ⌘⇧A to clear the whole proposal queue from anywhere in the app looks like the natural power-user move. It is the exact shortcut Guardrail 1 exists to forbid: no accept-all default, ever, per entry only. A3 reserves letters for accept and reject as a shared vocabulary; it does not get to decide what those keys do to more than one entry at a time. That decision, and the queue itself, belongs to C6.

What I would take

C, because the register already draws the boundary

Take C. C8 exists as its own decision precisely because Ask's real interface ( sources, five detail levels, follow-up questions, SSE streaming. Does not fit inside a 560px overlay honestly. Option A would either duplicate that page or degrade it. Option B is safer but asks a GM to memorise a second reflex for something that feels like the same instinct as searching for a name. C keeps the palette as the one thing you reach for, and lets it hand off to the surface that was actually built to answer.

Cheapest way to find out this is wrong: ship the question-classifier row with a generous trigger (anything with a question mark, or over five words, or starting with what/why/how/who) rather than a precise one, and watch the false-negative case: someone typing a real question that gets treated as a name search. If that happens often, the fallback in option B, a visible "press this to ask" hint on zero results, is one string change away and does not require touching the routing logic.

What this locks in

  • #104 the app shell has to reserve a trigger for the palette regardless of which shell shape A2 lands on; the icon rail, the sidebar and the palette-first option all need the same ⌘K to work identically.
  • #75 the palette's entity search has to hit the instant lane at the table (<100ms, §8), not the AI-routed slow lane; "who is this" during play cannot wait on a model just because it shares an input box with Ask.
  • #53 Ask mode is built against the assumption that the palette is one of its entry points, not its only one; a direct ⌘⇧A shortcut and a visible Ask button both have to land on the same surface C8 designs.
  • Deferred on purpose: the accept/reject queue interaction itself is C6's. This page only reserves the vocabulary (which letters mean what) so C6 does not have to invent one.
