Why this is a decision

F1 settled image generation: one action, always confirm the spend. F2 settled where the number lives: a meter in the shell, quota and warm budget on separate rows. D2 already takes consent for an import through its own pre-run estimate. None of the three says what the other paid actions do: an ambient audio layer, which F1 never covers, and a propagation plan, which has never been priced out loud anywhere in the first 38. Pick either one by accident and the product ends up asking for confirmation on some spends and not others for no reason a GM can articulate, which is its own way of making credits feel arbitrary even with a meter sitting right there.

SPEC 15 no opaque credits, never the word unlimited, and warming has a visible budget line "because it spends the model when nobody is watching, and an invisible spend is how a quota loses its meaning." This page is what that sentence means for every other paid action, not just warming.

Options

The same four moments, at the fixture's own numbers, run through each shape below. A fifth row, warming, rides along unchanged in all three: it has no click to attach a confirmation to, on a schedule the GM did not set, which is exactly why F2 gave it its own meter row instead.

A

Confirm every paid action

F1's dialog, extended to all four: cost shown, Generate/Cancel, before anything runs. Multiple units in one action (four layers, ten candidates) bundle into one dialog with one total, the same way F1 already bundles four image variants into one confirm.

Buys

  • Contradicts nothing already decided: F1's portrait dialog and D2's import estimate both already work exactly this way, this option just closes the two remaining gaps.
  • One rule, not four special cases: "this costs credits" always means the same interaction, so a GM never has to learn which actions ask and which do not.
  • Never a surprise, which is the same principle F1's own recommendation already leaned on: "the same principle F2 needs for imports."

Costs

  • One extra click on the propagation plan every single time, including the common case of a single small edit that only touches two or three entries.
  • F1 already names the risk of a dialog nobody reads: "a dialog people click through without reading defeats its own purpose, the risk is silent if it happens," and this doubles the number of dialogs a session produces.
  • Needs the exact per-credit numbers kept current in four places instead of one, the same maintenance cost F1 already flagged for its own single dialog.
B

Confirm above a threshold

A line at 10 credits. Below it, the action runs immediately and the meter absorbs the log entry; above it, the same confirm dialog as option A still appears.

Buys

  • Removes the exact friction F1's own cost list already worried about, one click every time on the cheap, common case, without touching the two expensive actions at all.
  • Lets F2's meter do the job it was built for: SPEC 15's "visible budget line" carries small spends instead of a modal manufacturing consent nobody reads.
  • One number to tune, rather than one dialog per action to maintain.

Costs

  • Directly reverses F1's decided behaviour for portraits: F1 already always confirms a 3 credit image, so this option either breaks that decision or has to carve portraits out as a named exception, which undoes the point of a single threshold rule.
  • A GM who fires four ambient packs in a row, 24 credits total, never sees a single number until the meter happens to be glanced at; SPEC 15's "slow bleed" failure, the one F2's own contextual option was rejected for enabling.
  • Ten credits is an arbitrary line with nothing in the spec to anchor it; it will need re-justifying the moment pricing changes underneath it.
C

Confirm once, then never

A single opt-in per universe, "this universe may spend credits automatically." After that, all four moments run silently forever, carried entirely by the meter.

Buys

  • The fewest dialogs of any option after the first session; a returning GM never sees another confirm for the rest of the universe's life.
  • One clear moment of consent to point to if a GM later asks why credits were spent, rather than reconstructing it from four different action types.
  • Genuinely simple to explain in onboarding (D7): "turn it on once, we'll ask before that, never again after."

Costs

  • Reverses both F1 and D2 outright: an import at 41 credits or a portrait at 3 stop ever asking, the exact "always confirm" and "estimate before anything runs" behaviour both pages already shipped.
  • A 41 credit import running unattended because of a click made weeks earlier is close to the "unlimited-feeling" spend SPEC 15 names by exclusion; the meter is the only evidence it happened, after the fact.
  • One opt-in covering every future action, of every size, forever, is a bigger single grant of trust than any of the fixture's individual actions actually need.

Rejected outright

A "stop asking me" checkbox on F1's own dialog

Smaller than option C and just as tempting: fold a mute toggle into the confirm dialog itself, so one click on one image generation quietly turns off every future confirm, not just for that action but for the account. It reads like a convenience, and it is the exact failure SPEC 15 names: no opaque credits, and a checkbox ticked once and forgotten is opaque by construction, with no universe-level boundary, no visible moment of re-consent, and no record anywhere except the meter that spend is now unlimited-in-practice. Option C at least makes the boundary a universe and a real screen; this shortcut has neither.

What I would take

A, confirm every paid action, unchanged from what F1 and D2 already ship

Take A. It is the only shape that does not reopen a decision the first 38 already closed: F1 confirms every image, D2 confirms every import through its own estimate, and this page's only real job is closing the two gaps neither one covers, the ambient pack and the propagation plan, with the same dialog shape rather than a new one. Bundling stays the same trick F1 already uses for four image variants: one dialog, one total, never one popup per layer or per entry. Warming stays outside this whole question by construction; SPEC 15 already settled that it never gets a click, only the meter row F2 already drew.

Cheapest way to find out this is wrong: ship A for one release and watch the propagation-plan confirm specifically, since it is the newest and most repeatable of the four. If GMs are visibly clicking through it without reading, the same tell F1 already flagged for its own dialog, promote propagation alone toward a threshold or a per-session pass, the way option B or C describes, rather than reopening the question for portraits or imports where nobody has shown that friction exists.

What this locks in

  • #66 the confirm dialog F1 built for image generation is the shared component, not a one-off: ambient pack generation reuses it, cost and Generate/Cancel included, so image and audio spend never drift into two different confirmation shapes.
  • #88 F2's "Recent operations" breakdown needs a propagation-plan row and an ambient-pack row at the exact numbers drawn here, 11 credits and 3 credits per layer, not placeholders left for engineering to fill in later.
  • #30 the propagation plan's own run goes through the same three job-lifecycle states D2 already defined for an import, queued, running, done, with the same pre-flight estimate-and-confirm step in front of it, not a second lifecycle invented for this one action.
  • Deferred: warming's exact trigger schedule and degradation order stay F2 and E2's (SPEC 8.1); this page only confirms that none of those triggers ever grows an interactive confirm.
